OPT-IN. It never rebinds the general gradient-surface foreground ramp; a bounded element or region may opt into it only once registered. It is not the default foreground and is not selected by font size. Density, legal, tabular, accessibility, or a comparable context may justify proposing a use — none of them authorizes one. Approved uses are registered in the repo README, under High-contrast foreground — registered uses; a new one requires measured need, explicit ASK authorization, and registration there before merge.

Browser / under-page edge

The area a browser paints beyond the document — the over-scroll pocket above and below the page — plus how it renders scrollbars and form controls. A browser derives the first from a solid background color, not from a gradient, and the second from color-scheme. Both are page-wide, so the foundation owns both on the root. --bg-edge is the semantic role; it binds existing palette values and creates none. It is painted on html beneath the gradient, so nothing visible on the page changes.

--bg-edge—
:root color-scheme—
html background-color—
body background-color—

Use the mode selector above to check all three theme paths. body stays transparent on purpose: the root carries the solid, and the root's background is what propagates to the canvas.

These readouts are necessary, not sufficient. They show the values the browser is being handed. The pocket itself sits outside the viewport and cannot be judged in a desktop window — confirm it on a real device by over-scrolling past the top and bottom of the page in both light and dark.

Textual link unboxed · canonical .surface-text-link

A link inside running prose or a structural title, opted in by class. The resting rule is the emphasis accent at partial opacity — its own hue at a reduced dose, never mixed toward the foreground. Hover raises it to full opacity. Focus is governed separately and independently. The module declares no text color: an ordinary link inherits its context, and a role-colored anchor keeps its own.

This is the default-ASK treatment, and no strict AA claim is made for it. The resting underline measures 1.72:1 and 1.82:1 against the light gradient stops and 2.11:1 and 2.23:1 against the dark — below the strict 3:1 non-text floor in both themes. In light that floor is unreachable at any opacity, full included; in dark a higher opacity would reach it, but that would be a different treatment from the single uniform default. The affordance rests on the presence of a rule where the surrounding prose has none, plus the independently governed focus indicator, which does clear its own requirement. No AA alternate ships in this unit.

The design system is published at design-system-ASK, and the catalog lists every surface and artifact pattern it exhibits.

A consuming role may color its own anchors, and the module leaves that alone: this link is deliberately quieter than the prose above it, and carries the same rule.

Top: ordinary prose links, inheriting the payload foreground. Bottom: an anchor its own role colors to --fg-3, unchanged by the module. Hover either to see the rule rise to full opacity, and Tab to one for the independent focus indicator.

A shaped object announces itself by geometry and takes no class: compact action — while an unboxed link announces itself only by its rule.

Treatments // by physical color

Each shared treatment, in each physical color a governed meaning admits, drawn by the module that owns it. A caption names the physical color and the application that draws it there. A color with no application is listed, not drawn. The status words are the README's application coverage statuses: supported, proposed extension, not implemented and not applicable. Painting a color does not admit a meaning.

Rails five families · surface-treatments.css · surface-document.css

Rails share paint, not place or meaning. A passage rail sits at the content edge and insets its text; a scope rail sits in the outer lane beside the range its label governs, in the label's color: neutral, a review judgment's, or a keyed state or evidence role's; an assessment rail marks one summary in a comparison table; the hierarchy rail is a quiet 1px rule; not yet testable takes a 2px dashed rail. Rail paint is keyed by physical color: --surface-rail-paint-green, -yellow and -red, one paint per color whichever meaning draws it, each none today, the plain 2px stroke. The earned, structural and deflated names are aliases that read their color's paint.

Semantic applications // coverage and admitted applications

A shared treatment is reusable; a semantic system uses it only where its contract binds it. The README's application coverage is the one map of which representations each system has, in which context, and in which status. Each key presents its system in one order: scope, roles and colors, representations, rules, worked applications, usage and owners.

  • Spectral State // the state of an architectural element
  • Evidence State // what the evidence supports
  • Review Semantics // the judgment asked or made on a document's own content
  • Criterion Assessment // how a characteristic serves a stated criterion
  • Three Functions // the legislative, executive and judicial roles of an apparatus

Admitted applications three applications · supported

Three applications of existing treatments, each bound by its own system and drawn here by the modules that bind them. Each keeps its system's words beside its color. None applies inside a multi-axis review annotation, where the square, the dot, the outline, the range and the passage mark stay the channels.

A // Spectral State labels and rails

supported Context: an architecture description, a figure caption or a table that names an element's state in words, outside a multi-axis review annotation; inside one, the square keeps the state channel. Binding: spectral-state.css binds each chromatic role's value to the label's edge and, through the label at a range's head, to the range's scope rail, with green's, yellow's and red's rail paint. The words stay in the label role and nothing fills, so no ink is needed. The label names its axis, so a green edge never reads as an accepted review. Neutral takes no keyed label.

C // A decision record: the panel and the node

supported Context: a standalone decision record. In a review summary or a status board it is a panel; in a diagram, a decision node. Inside a reviewed document the review mark, the range and the passage mark stay the channels; neither replaces them. Binding: review-semantics.css binds each pending or decided role's Review State value on .review-record. A panel takes it as PERIMETER PAINT's color and as its outcome label's border, and its words keep the theme's text roles; the perimeter blooms alike for all four outcomes. A node, declared with data-record-presentation="node", takes it as FILL PAINT's color, with that color's existing ink as --review-*-ink. Each record states its outcome in words and names, in fields of its own, what it concerns, who decided or decides and the scope, and any material condition. It is inert, and its color confers no authority.
