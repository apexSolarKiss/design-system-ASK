every representation the roles have, and its status // the same rows as the README's application coverage

  • supported filled node or mark, in its role's ink · a consumer-composed state-bearing figure, such as the interactive spine and radial and the key · spectral-state.css binds the role and surface-treatments.css FILL PAINT paints it · Spectral State key
  • supported the neutral filled shape · a node that asserts no state in a state-bearing figure, such as the spine and the keys; not the radial's no-state marks, which keep the pattern's wash, or a structural diagram's node · FILL PAINT's neutral shape · Spectral State key
  • supported state square, with its label · a document annotation · review-semantics.css · Review Semantics key
  • supported stroke or text in one role's value · a consumer's own figure · spectral-state.md, How to use it: a composition from the role tokens · no key specimen
  • not implemented standalone state label, and its range rail · a document, caption or table naming an element's state in words · adopted; the bordered label and labeled range admit no state color · candidate A, described in the style guide
  • not applicable any state color · diagram-static-H, -V, -SEQ and -FLOW · those patterns are state-free
  • not applicable a button, link, alert or status chip · any interface · the closed palette

Rules // sparse-signal discipline

most nodes neutral // neon only to say something

a shared value is not a shared meaning // Evidence State, Review State and Criterion Assessment reuse these values under their own words

Worked applications // the roles in use

interactive spine // filled state nodes beside neutral ones, with selection and export

interactive radial // state marks filled, structure washed

Review Semantics // state squares in a document annotation

Usage and owners // load order and who decides what

load colors_and_type.css first, then spectral-state.css with surface-panel.css and surface-treatments.css, all from one design-system commit // spectral-state.css declares custom properties only, so its place beside the other two changes no resolved value; this key loads it directly after the foundation

spectral-state.css owns the roles and their values // surface-treatments.css owns the fill paint and every ink // the consumer owns which element carries which state, and its evidence
