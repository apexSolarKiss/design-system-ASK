This skill is a downstream implementation of ASK's canonical `visual-identity-system.md`. When this skill and the canonical file disagree, the canonical file wins.

Read the README.md file within this skill, and explore the other available files.

Key files:
- `surface-panel.css` — shared presentation contract for live content panels
- `surface-action.css` — shared presentation + interaction contract for compact action controls
- `surface-text-link.css` — shared presentation contract for unboxed textual links: an opt-in `.surface-text-link` for a link inside running prose or a structural title, which has no geometry announcing that it is operable. It is the third root-level visual rule and the distinction from the other two is the whole point: a panel and a compact action are **shaped objects** whose form already communicates interaction, so they carry their own grammar and never this one. The module declares no text color, carries a theme-resolved magenta-derived underline held to the 3:1 non-text floor, raises that rule to full magenta on hover, and takes an independent high-contrast focus indicator. Opt in by adding the class to a qualifying link; never by adding shaped objects to a deny-list.
- `patterns/surface-shell/surface-shell.css` — shared live-surface shell and structural-title contract
- `README.md` — voice, visual foundations, iconography, caveats
- `colors_and_type.css` — drop-in CSS variables (light + dark) and base type rules
- `fonts/InterVariable*.woff2` — Inter variable font (interface + display)
- `fonts/JetBrainsMono*.woff2` — JetBrains Mono variable font (code + technical/tabular + structural locators + compact actions)
- `assets/logo-ASK.svg` — vector wordmark, **primary** (`fill: currentColor`; the consuming surface sets `currentColor` to the mode-specific wordmark pairing, not the body text color)
- `assets/logo-ASK-white.png` — raster wordmark in `#FFFFFF` (light-mode pairing / fallback)
- `assets/logo-ASK-lavender-ASK.png` — raster wordmark in lavender-ASK `#D4C6E1` (dark-mode pairing / fallback)
- `preview/styleguide.html` — the live token styleguide (look at it before designing)

Cardinal rules — do not break without explicit permission:
1. **Type** — Inter is the default for interface prose, supporting copy, and display. JetBrains Mono is the code + technical/tabular family, and it also carries explicit named roles: the **structural locator** (24px / 300 / 1.12 line-height / -0.02em tracking, implemented canonically by `.surface-title`; the `surface-shell` **breadcrumb** form alone takes a pattern-local 1.35 leading for wrapped-fragment clearance, and shares every other declaration) and the **compact action** (14px / 300 / 1.20 line-height / 0 tracking, implemented canonically by `.surface-action`), among the live-surface set enumerated below. The **panel primary label** (`.surface-panel-title`) carries the identical 24px / 300 / 1.12 / -0.02em metric but is **Inter**, and it keeps 1.12 — the breadcrumb exception is the shell's, not the role's. Family is owned by the selector, never by the label's text: `.surface-title` is mono in both of the shell's title forms — the root-level plain heading and the breadcrumbed subpage title — and `.surface-panel-title` is Inter whatever the panel is called, a technical or structural name included. The two title forms differ in leading and in nothing else: plain stays on 1.12, breadcrumb takes 1.35. The compact action is Caption-*sized*, not the Caption role — no uppercase, no wide tracking, no 400 weight, and never Inter. Body prose and supporting copy stay Inter. Mono is allocated by explicit selector in the owning module or pattern. The current live-surface allocation is: the foundation's technical utility (`code` / `kbd` / `pre` / `samp` / `.mono` / `[data-mono]` / `.tabular`); `.surface-action` for the compact operative control; `surface-shell`'s own chrome in `.surface-title`, `.surface-badge` and `.surface-footer`, the last of these on the Caption size step alongside the compact action; and a consuming surface's own explicitly named operative control, such as the style guide's `.surface-theme`. **That is the live-surface set, not a repo-wide census** — the artifact and diagram patterns own additional pattern-local technical and structural mono selectors, under the same principle and with no page-default consequence. Everything else is Inter unless the owner of a selector says otherwise. Nothing becomes mono for being interface-facing, for being a `<button>`, or for containing `//`. Weights by role: generic H1/H2 display 400; H3, both primary-label implementations and compact actions 300; body 200 ExtraLight at 24px; supporting copy Small Inter 300. Defined role sizes may differ — never invent an ad-hoc size merely for emphasis. A primary label stays 300 even when its semantic element is an h1 or h2. The style guide's 18px Inter **CTA** specimen is a separate role and is not conformed to the compact action.
2. **Backgrounds** — only the two diagonal gradients. Light: `linear-gradient(45deg, #D4C6E1 → #E2D3F0)` with `#6A637F` default foreground (`#FFFFFF` is the light-mode wordmark pairing only, never body text). Dark: `linear-gradient(45deg, #201D26 → #0A090C)` with `#D4C6E1` text.
3. **Color palette is closed** for brand surfaces, general UI, chrome, emphasis, and interaction state. The core set (`#FFFFFF` wordmark · `#6A637F` default light foreground · `#E2D3F0` / `#D4C6E1` light gradient · `#201D26` / `#0A090C` dark gradient, with `#201D26` doubling as the opt-in high-contrast foreground — never a rebind of the gradient-surface foreground ramp; a bounded element or region may opt in only once registered. Never the default foreground, and never selected by font size. Approved uses are listed in the repo README under **High-contrast foreground — registered uses**; a new one requires measured need, explicit ASK authorization, and registration there before merge) + surface (`#BFB3D4` / `#C9BCDE`) + two UI accents (`#8B79A2`, `#AE87C2`) + three emphasis accents (`#FF00FF`, `#AA40FF`, `#00BEFF`, sparing). No other values are available as unrestricted general-purpose colors. The **foundation-level** opt-in exceptions are the **ASK semantic-color primitives** for data / architecture visualizations, not general UI color: the **Spectral State** family (`spectral-state.css`) and its sanctioned profiles (e.g. `evidence-state.css` — Evidence State) for element / evidence *state*, and **Three Functions** (`three-functions.css`) for structural *function* (`legislative` / `executive` / `judicial`). Both bind roles to the closed palette; neither expands it. The bounded exceptions sit on three distinct axes — **semantic state** (Spectral State / Evidence State), **structural function** (Three Functions), and **participant identity** (pattern-local). The third: the Class B **`message-archive`** participant-identity ramp, which softens the emphasis hues for *participant identity* (which person — never state, status, or emphasis). Those derived values are **pattern-local**: they are not foundation tokens, are not general-purpose colors, and authorize no use outside that pattern.
4. **Voice** for system surfaces is calm sentence-case, impersonal/declarative. No studio "we". No emoji in design-system surfaces. No marketing adjectives. Do not import ASK's personal "terminalcore" voice (slash-slash em dashes, plus-for-ampersand) — that's ASK's personal channels, not this system.
5. **No icons by default.** If absolutely needed, stroke-only at 1.25 weight, `currentColor`. Never emoji as icons.
6. **Scope is the meta-brand.** Sub-brand theming (production, builder, artist) layers elsewhere, not here.

If creating visual artifacts (slides, mocks, throwaway prototypes), copy assets out and create static HTML files for the user to view. Link `colors_and_type.css` and inherit its tokens — don't redefine them.

For static artifacts, also:
- copy or sync the design-system-ASK files you reference (`colors_and_type.css`, fonts, required assets) into the artifact bundle, rather than linking outside it
- record which design-system-ASK commit the artifact inherited from, when practical, so the freeze is traceable
- let `colors_and_type.css` handle light/dark: explicit `data-theme="dark"`, explicit `data-theme="light"`, the `.theme-dark` class, and the `prefers-color-scheme` OS preference all resolve correctly without artifact-side overrides
- follow cardinal rule #1 for type and cardinal rule #3 for color

Static artifacts freeze inheritance at render time; production code may use a live dependency or import model if appropriate.

If working on production code, inherit the canonical token carrier rather than transcribing its values: use a live import or a pinned vendored copy of `colors_and_type.css`, keeping the `--ask-` namespace intact. Where the host architecture requires semantic aliases, map them through an explicit adapter that resolves to the imported or pinned vendored canonical carrier. A transcription or adapter is not the canonical token source and does not establish ASK-family parity. Read the rules here to become an expert in designing with this brand.

If the user invokes this skill without any other guidance, ask them what they want to build or design, ask some questions, and act as an expert designer who outputs HTML artifacts _or_ production code, depending on the need.
