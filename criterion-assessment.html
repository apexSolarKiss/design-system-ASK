Criterion Assessment

How does this characteristic serve the stated criterion? Favorable, caution or adverse, against a criterion the author declares, or unassessed. The profile owns what each role means and how it is drawn; the author owns the criterion and every assignment.

Scope // how a characteristic serves a stated criterion

A profile under Spectral State for comparisons: each assessment answers one criterion the author declares, with its direction, its scope and the basis of the rating. A rating never comes from a letter, a position or a neighboring figure, and a characteristic with no declared criterion stays unassessed.

Roles and colors // four roles, three colors

  • favorable // value of state-earned

  • caution // value of state-structural

  • adverse // value of state-deflated

  • unassessed // no rail

The three colors are Spectral State's, by reference: one value each, the same in both themes, and each rail is a plain 2px stroke on either field. They are visual-role mappings, not aliases: a surface keeps the words Favorable, Caution and Adverse, and never writes earned, structural or deflated for them.

Representations // where the roles are drawn, and their status

The table application is rail-only: a rail and its word, a legend-led key, or a value field, never a fill or a tint. A node in an assessment-bearing figure is filled instead, in its role's color and that color's existing ink, and shows its word, or the figure has a key. An unassessed node keeps the figure's own node, here the neutral shape, and shows no word.

Rules // an assessment beside a review mark

In the worked comparison below, the PDF's fidelity cell carries two judgments, and each keeps its own form. Its caution rail says how the PDF serves the row's criterion. Its open question is a review mark from Review Semantics: its own bordered box, its own color and its own words. The mark does not make the caution a review decision, and the rail does not answer the question.

The same holds for an evidence mark. A favorable characteristic is not a supported claim, and a supported disadvantage is still adverse.

Rules // one paint per rail color

How a color is painted as a rail belongs to the surface treatments, not to this profile: a rail in one color takes the same paint whichever meaning draws it. This profile binds each role to its color's paint, as Review Semantics binds a review range's and Spectral State a keyed range's. Here a declined range and an adverse assessment share one red, an accepted range and a favorable assessment one green, and a structural state range and a caution assessment one yellow, each rail in its own place: a range's in the outer margin, an assessment's in its lane.

State // Structural

The tracking schema is proven; the full flow has not yet run under load.

  • favorable // the accepted range's green

  • caution // the structural range's yellow

  • adverse // the declined range's red

Caution's yellow is the same plain stroke beside a summary, in a value field and in a key on this page, and beside the structural state range above. A review range is never yellow, and an assessment never opens a range.

Rules // plain on both fields

Each rail is a plain 2px stroke in its color, on the light lavender field and the dark ink alike. Spectral State gives each color one value in both themes, and in it every rail reads on both fields. Until Spectral State v1.2 the light theme took a deeper yellow, which as a bare rail all but disappeared on the lavender, so caution's rail took a 1px same-color ring there; that ring is retired with the value it answered.

as shipped // the plain stroke

  • favorable // plain

  • caution // plain

  • adverse // plain

A rail's paint is the surface treatments' one rail paint, so a review range in green or red takes the same paint as favorable and adverse. Each color's paint is none today; a dose added there later would be measured on the field it answers and would reach every rail in its color. Not this rule: a bordered label's edge, which every label takes per theme, a diagram's stroke, a dot or a square.

Worked applications // a worked comparison

Three ways to deliver a reviewed document, against four rows. Each assessed summary carries one rail in its cell's lane, beginning on the edge its column's header begins on, and the word that names it; the rail is as tall as the summary and its word, never the row. The last row declares no criterion, so its summaries carry no rail, and their text sits where the others' does.

Worked applications // a legend-led comparison

The same three options, with a row of summaries and two rows of figures. The table is legend-led: its key names each rail, so the words stay in the cells as text for assistive technology and draw nothing, and each rail is as tall as its summary or figure. Each summary spans its family's columns, so its rail begins where the family's header does. The figures share a value field, as wide as the template 000.00 that their widest needs: each sits at its column's end, and in each column the rails share one line, 12px before the field, however wide the figure. A sighted reader reads these assessments from the rails' colors against the key, so the worked comparison above keeps its words.

Usage and owners // load order and who decides what

Load criterion-assessment.css after spectral-state.css, surface-document.css and surface-treatments.css, whose rail paint and fill inks it binds, all from one design-system commit, in the order its contract gives. The profile owns what each role means and how a table or a filled node draws it; the surface treatments own each rail's paint and each fill's ink; the author owns the criterion, its direction and scope, and every assignment.
